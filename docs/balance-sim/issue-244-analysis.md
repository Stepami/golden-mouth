# Issue #244: синтетический корпус и сигналы моделей

05.11.2026. [Корпус](issue-244-corpus.json) содержит 23 вымышленных поста четырёх миров: обычные записи, три близких повтора, обращения против аудитории, критику решений, пустые обещания, посты не в тему, юмор, смелую позицию, короткий и длинный текст. Тексты игроков не использовались. [Скрипт](issue_244_collect.py) обращается к локальному Infinity v2; [выходы](issue-244-model-outputs.json) получены с закреплённых mini-frida и MiniLM. Для NLI сохранены также [первая](issue-244-model-outputs-v1.json) и [вторая](issue-244-model-outputs-v2.json) формулировки гипотез.

| Сигнал | Наблюдение на корпусе | Вывод |
|---|---|---|
| Близкий повтор | Косинусное сходство трёх заданных пар: `0,761`, `0,825`, `0,776`. | Нужны отрицательные пары и проверка точного максимума, прежде чем выбрать границу. |
| Слабая связь с миром | Два поста не в тему: `0,054` и `0,214` к описанию мира; остальные посты не ниже `0,354`. | В этом корпусе есть зазор, но двух отрицательных примеров мало для трёх игровых сложностей. |
| Против аудитории | В первом варианте NLI-гипотез целевые посты дали entailment `0,075` и `0,031`; длинный разбор без нападок дал `0,085`. Во втором варианте один целевой пост и критика решения дали одинаково `0,041`. | Общий порог смешивает обращение против людей с критикой идеи. |
| Пустое обещание | В первом варианте три целевых поста дали `0,016`, `0,029`, `0,007`; обычный длинный разбор — `0,101`. | Общий порог не выделяет пустые обещания. |
| Юмор | Во втором варианте три шутки дали `0,537`, `0,579`, `0,446`; обычная запись — `0,551`, пост не в тему — `0,502`. | Порог для спасения юмором заденет обычные записи и пропустит одну шутку. |

MiniLM прошла техническую проверку: очевидная идентичная NLI-пара дала entailment `0,755`, явное отрицание — contradiction `0,995`. Проблема здесь в применимости общих игровых гипотез, а не в загрузке ONNX или адаптации пары к `/classify`.

Пороги easy/normal/hard и размер потери **не подобраны**. Прогон старого и нового баланса не имеет смысла до выбора сигналов, которые разделяют случаи на синтетическом корпусе: подмена выходов моделей случайным `IsFlop` нарушила бы условие #244. `docs/config/balance.json` и `docs/game-flow.md` не менялись.

## Проверка альтернатив 05.11.2026

После решения пересмотреть подход проверено сходство mini-frida с синтетическими примерами каждого признака методом leave-one-out: [скрипт](issue_244_exemplar_probe.py), [полный вывод](issue-244-exemplar-output.txt). Для «против аудитории» два целевых поста получили по `0,435`, но обычный пост — `0,693`. Для «пустого обещания» целевые `0,381–0,490`, шутка — `0,719`. Для юмора целевые `0,245–0,282`, обычный пост — `0,539`. Этот подход также не даёт безопасных порогов.

У [mDeBERTa-v3-base-mnli-xnli](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli) (MIT) есть INT8 ONNX. Его tokenizer принимает строковую пару с `[SEP]`, получаются точно те же токены, что у `tokenizer(premise, hypothesis)`. На Docker Desktop с 2 CPU и 4 GiB RAM модель не загрузилась вместе с mini-frida: контейнер дважды завершился с `OOMKilled` при лимите 3,5 GiB, в том числе после отключения прогрева и ONNX-оптимизации. Одиночный запуск тоже исчерпал память доступного Docker Engine; до сбора NLI-оценок дело не дошло. Это ограничение локального железа, качество модели на корпусе не оценено.

Компактная [Horizon-Labs/multilingual-zeroshot-small](https://huggingface.co/Horizon-Labs/multilingual-zeroshot-small) (Apache-2.0, INT8 ONNX, 141M параметров) загрузилась **вместе** с mini-frida в одном Infinity v2 с лимитом 3,2 GiB. После загрузки память контейнера была около 1,5 GiB без прогрева и ONNX-оптимизации, batch size 4. Строка `premise + "<eos>" + hypothesis` дала те же токены, что парный tokenizer. [Выходы на том же корпусе](issue-244-horizon-outputs.json) и [сравнение гипотез](issue-244-hypothesis-output.txt) показывают улучшение только для одного признака: гипотеза «The audience's opinion does not matter» дала двум постам против аудитории `0,107` и `0,339`, максимум остальных 21 примера — `0,047`. Для пустого обещания и юмора разделения по проверенным гипотезам нет: например, у обещания в мире Айти entailment `0,038`, а у критики идеи `0,475`; у шуток `0,045`, `0,176`, `0,002`, у смелого поста без шутки `0,226`. Поэтому этот кандидат тоже не обосновывает все пороги #244.

Дополнительно проверены [восемь новых синтетических формулировок](issue-244-holdout.json): по одному посту против аудитории и одной критике идеи в каждом из четырёх миров. Для русской гипотезы «Мнение аудитории не имеет значения» четыре целевых поста дали `0,072–0,965`, четыре критики — `0,005–0,041`; для английской формулировки целевые `0,051–0,943`, критики `0,006–0,009`. Это подтверждает только перспективность **данного** признака на небольшом корпусе, не пригодность остальных порогов. Тексты holdout-прогона не являются текстами игроков.

## Повторная проверка после увеличения Docker RAM до 8 GiB

05.11.2026, Docker Desktop: 2 CPU, 7,76 GiB доступно Engine. Каждая модель работала **вместе с mini-frida в одном Infinity v2**, без прогрева и ONNX-оптимизации, batch size 4. Для больших моделей лимит контейнера — 5 GiB; для MiniLM и Horizon small — 2,5 GiB. Все запросы использовали один и тот же синтетический корпус. Это локальные замеры, а не прогноз производительности целевого сервера.

Крупные артефакты: [Horizon base](https://huggingface.co/Horizon-Labs/multilingual-zeroshot-base) `a9a5a24e58c794a0f7532d3de842236435a9ae22` (Apache-2.0, INT8 ONNX 641 MB) и [mDeBERTa](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli) `8adb042d524ecd5c26d3e3ba0e3fbcf7e2d0864c` (MIT, INT8 ONNX 339 MB). Они загружались из локальных файлов без сети внутри Infinity. Это экспериментальные кандидаты, текущий Compose по-прежнему использует MiniLM.

| NLI | RAM Infinity после запросов | 48 запросов при concurrency 8 | p95 при concurrency 8 | Качество на корпусе |
|---|---:|---:|---:|---|
| MiniLM INT8 | 1,66 GiB | 16,0 req/s | 563 мс | Общие гипотезы не отделили нужные случаи. |
| Horizon small INT8 | 1,58 GiB | 6,3 req/s | 1484 мс | Есть сигнал против аудитории; обещание/юмор пересекаются. |
| Horizon base INT8 | 3,00 GiB | 2,5 req/s | 3609 мс | Против аудитории отделяется лучше; обещание/юмор всё ещё пересекаются. |
| mDeBERTa INT8 | 3,17 GiB | не замерено | не замерено | На том же корпусе и с [несколькими гипотезами](issue-244-mdeberta-hypotheses.txt) улучшения для обещания/юмора нет. Медиана короткого batch из трёх пар — 188 мс против 31 мс у MiniLM. |

Полные данные: [mDeBERTa](issue-244-mdeberta-outputs.json), [Horizon base](issue-244-horizon-base-outputs.json), [варианты гипотез base](issue-244-horizon-base-hypotheses.txt), одинаковый [нагрузочный скрипт](issue_244_load.py) и его выводы для [MiniLM](issue-244-minilm-load.txt), [Horizon small](issue-244-horizon-small-load.txt), [Horizon base](issue-244-horizon-base-load.txt). У Horizon base два целевых поста против аудитории получили `0,459` и `0,413`, максимум остальных 21 записи — `0,044`. На [дополнительных примерах](issue-244-holdout.json) base дала четырём целевым `0,096–0,905`, четырём критикам идеи — `0,001–0,006` (английская гипотеза). Но по пустому обещанию на основном корпусе цель `0,106–0,319` пересеклась с длинным обычным разбором `0,203`; одна шутка получила `0,019`, а пост без шутки — `0,226` по юмору.

Вывод для лимита ресурсов: дополнительные 4 GiB позволяют запускать более крупные модели, но не дали подтверждённого решения для всех требуемых признаков. Horizon base примерно в 6 раз медленнее MiniLM по throughput на тех же 2 CPU и занимает почти вдвое больше RAM. Для роста нагрузки нужен запас и по CPU; заменять runtime-модель только ради этого корпуса преждевременно. Действующий `balance.json` не менялся.
