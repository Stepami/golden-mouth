## Границы, которые требуют серверной работы

| Возможность прототипа | Чего нет сейчас | Связь и следующий шаг |
|---|---|---|
| Персональная большая история | Текущей главы/узла, статуса, условий, общего прогресса, персональной цели и допустимого следующего действия | #192 + контент #195. Главная цель/главы/чекпоинты должны приходить по персонажу и экземпляру мира. Не строить историю из числа постов. |
| Зачёт по смыслу | Надёжного подтверждения сюжетного действия | #177/#192/#193. Свободный пост не двигает автомат без явной привязки story_ref. Возврат после сети использует тот же идентификатор операции. |
| Первый пост под роль | Сохранённого персонального старта и безопасного текста начального предложения | #195/#192. В текущем переносе контекст прежний; чужую ветку не выдаём за новый персональный сценарий. Текст пользователя не заменяется автоматически. |
| Генерация своего мира | Генерации из описания/голоса, транскрипции, статусов сборки и редактируемого результата | #152, согласовать с #192: генерировать место, состав, роли, завязку и черновик автомата из одной идеи. Сначала редактируемый черновик, затем явное подтверждение. |
| Ровно четыре персонажа | Единого ограничения состава: в текущем пресете 3 NPC, выбранный готовый герой удаляется из NPC; свой герой добавляется отдельно | Нужен единый контракт «игрок + 3 NPC», включая замену роли в собственном мире, без незаметного возвращения выбранного NPC. До согласования текущий состав серверных миров не меняется. |
| Обложки/аватары | Генерации по контексту, хранения загрузок, безопасной замены/удаления | Нужны ресурсы изображения, состояние генерации и сохранение выбора. DiceBear и текущие обложки остаются рабочим вариантом. |
| Подарок дня | Награды дня, доступности, подтверждения получения, инвентаря | Серия входов — не API подарка. Нужен серверный календарь/часовой пояс, однократное атомарное получение и защита от повтора. Уменьшенную карточку подарка подключать к этим данным. |
| Кристаллы/бусты | Баланса, источников получения, инвентаря, покупки и применения | Нужен отдельный согласованный контракт. Экран не обещает покупку, когда сервер её не сохраняет. Цена из демо не утверждает экономику. Покупка и успешное применение должны быть атомарны/идемпотентны; ошибка публикации не списывает буст. |
| Наборы достижений | Статуса «готово/забрано», условий, награды, переключения набора | Текущая collection не заменяет эту модель. Следующий набор открывает сервер после получения полного предыдущего. Не вычислять по одной надписи. |
| Игровые дни | Номера дня истории, границы дня/этапа, событий перехода | Не путать календарь серии, сброс энергии и сюжетный день. Определить их влияние в #192 до реализации UI перехода. |
| Точный XP от поста | Сохранённого изменения навыков в PostResult | Расширение результата: значения до/после, повышение уровня, использованный буст. Разницу между двумя загрузками профиля не приписывать одному посту. |
| Полный журнал | Получения исторических результатов по миру/посту и восстановления на другом устройстве | Нужна серверная пагинация и изоляция по владельцу/worldId. Локальный журнал — временная полезная версия, не серверная история. |
| Twitter-действия | Личного лайка/счётчика, репоста/отмены, связи цитаты с исходным постом, оценки 1–5 | Остались предложением #205. Emoji-аудиторию не складывать в выдуманные лайки. Уточнить цену/XP перед реализацией. |

## Как наслаивать сюжетку

Визуальный перенос не должен ждать полного наполнения всех глав. Но контракт автомата надо согласовать до его интеграции, а не после завершения всего редизайна.

1. Проверить текущие экраны на живом API и принять компоновку в #205.
2. Согласовать документы #195/#192 и минимальный контракт: идентификатор/версия истории, цель, главы/чекпоинты, активный узел, разрешённые действия, story_ref, пауза/продолжение, знания NPC, права и повтор операции.
3. Реализовать серверный исполнитель и контентную миграцию отдельными PR. Миграция описаний сама автомат не запускает.
4. Подключить поля автомата к уже выделенным экранам завязки, редактора и истории; убрать временные ориентиры там, где пришла персональная история. Проверить роль, свободный текст, смену мира, восстановление и повтор.
5. Для собственного мира применять тот же контракт. Генератор предлагает начальный контекст и черновик истории, пользователь редактирует; сервер валидирует связность/достижимость и подтверждает публикацию. Произвольный пользовательский текст не становится исполняемым правилом без проверки.
6. Отдельно подключить экономику/изображения/достижения. Согласованные внешние задачи не создаются автоматически из этой таблицы.

## Проверка

- TypeScript и production build выполняются в DEV-окружении.
- Проверяются реальные загрузки каталога, ленты, профиля, настроек, обсуждения; 320/390 px, обе темы, отсутствие горизонтального переполнения и ошибок JS.
- Публикация/неизвестный исход/ошибки/разные миры проверяются дополнительно управляемыми ответами API без расхода ресурсов пользователя. Это не доказательство качества AI или серверной атомарности.
- Перед PR — проверка секретов и diff; продуктовые изменения бэкенда в этот перенос не включены.
