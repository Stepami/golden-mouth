# Экраны фронта против макетов

Объём проверки выбирать по риску правки согласно `frontend/AGENTS.md`. Для локальной правки проверить затронутый экран и основное действие; общий компонент не требует автоматически всех сочетаний миров, ширин и браузеров. Расширять проход перед выпуском либо при изменении общей логики, навигации или адаптивности, выбирая затронутые сценарии. Обязательные проверки перед PR сохраняются; успешные проверки без новых оснований не повторять.

1. На Mini, в checkout проверяемой версии: `cd frontend && scripts/screens.sh <коды экранов>`. Скрипт собирает фронт, поднимает preview и снимает 390×844 в `frontend/shots/<код>.png` (режим `?shot`: ширина 390 по центру, анимации выключены). Без аргументов снимает весь реестр — использовать только для полного прохода. Если сборка уже проверена на этой версии, можно снять нужные экраны существующим браузерным инструментом без повторной сборки. При недоступности Mini сообщить блокировку, не переносить сборку на Air.
2. Проверить, что снимки показывают нужный экран, а не пустую страницу или ошибку. Малый размер файла — повод посмотреть изображение, а не доказательство сбоя.
3. Положить рядом `docs/screens/<код>.png` и `frontend/shots/<код>.png` и сравнить глазами: тексты, порядок блоков, одна главная кнопка, одна жёлтая плашка, цвета и отступы. Числа в тестовых данных могут отличаться от макета, это не ошибка.
4. Тексты: системные фразы без рода; мир игрока через `worldOf(player.world)`, а не «Сцена» руками.
5. Новый экран без макета: снять и положить в `docs/screens`, добавить строку в `docs/screens/README.md` (раздел «Экраны без макета»).

Если макет и экран расходятся по смыслу, прав `docs/game-flow.md`: чинить то, что с ним не совпадает.
