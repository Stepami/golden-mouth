## Идентичность и происхождение

WorldId — доменный `Vogen<Guid>`, BSON UUID Standard; JSON UUID — формат D. Символьные `evening`, `sorcerers`, `houses`, `it` в заголовках — редакторские ключи, не значения route/query. Точные UUID и порядок обновления определены [миграцией 2.5.0](../migrations/2.5.0-worlds.md). Существующие UUID экземпляров, имена, StarId и AvatarSeed сохраняются.

TemplateId: WorldId? хранит происхождение на сервере. Выбор истории использует происхождение пресета и явную роль, а не Difficulty/BalanceKey. Для мира с нуля TemplateId=null; ID экземпляра назначает сервер. PUT сохраняет исходное происхождение. WorldResponse не возвращает TemplateId и IsArchived: будущему исполнителю нужно явно согласовать идентификацию сюжетного пресета в своём контракте, не выводить её из названия. Архивные stage/academy/stream/own не возвращаются в активный каталог.

Используются существующие доменные WorldId/PlayerId/PostId/CommentId/StarId/AuthorId и штатные binding/JSON/OpenAPI Vogen. AuthorId сохраняет префикс Player_/Star_. RequestId, story_id и WantId — свои строковые ключи; новые обёртки для них этим PR не вводятся. Лента и свои посты используют cursor/pageSize → items/nextCursor после #211, не PageNumber.

## Сложность, баланс и повтор

BalanceKey и Interface.Difficulty удалены. World.Difficulty — самостоятельная настройка easy/normal/hard, по умолчанию normal при создании/редактировании; коэффициенты выбираются из balance.difficulties. Отдельного own-профиля нет. Доступ к миру с нуля определяется постоянным HitOwnWorldMilestone и access.create_world_from_scratch; сложность и сюжетный режим его не меняют.

В действующем двухшаговом флоу подтверждение публикации использует текущую сложность мира и актуальный баланс, включая ранее начатые незавершённые публикации. Снимок коэффициентов/сложности не сохраняется. Завершённый результат при повторе не пересчитывается. Версия сюжетной политики, её проверка до списания и сохранённая квитанция остаются отдельными требованиями будущего исполнителя.

Таблицы XP/стоимости в balance-check не требуют пересчёта от смены структуры профилей: energy/skills/thread сохранены. Примеры роста для пресетов предполагают их текущую сложность (evening easy, sorcerers/houses normal, it hard). Они не доказывают результат для изменённой игроком сложности. Прежний own-профиль нельзя использовать для новых расчётов; на normal применяются коэффициенты normal.
