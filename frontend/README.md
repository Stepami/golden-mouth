# frontend

Telegram Mini App игры «Реки». Правила для агента и людей: [AGENTS.md](AGENTS.md). Навыки агента: [apm.yml](apm.yml).

Источник данных задаётся в единственном `public/runtime-config/config.js`. `apiMode: 'mock'` использует локальные игровые данные, но шаблоны миров загружает с сервера, `apiMode: 'backend'` направляет запросы на same-origin `apiBaseUrl`; сейчас файл настроен на backend. Local Compose запускает Vite dev server и проксирует `/api` в backend.

В local Compose Vite-плагин читает общий `TG_PAT`, даёт `@tma.js/sdk` вымышленного игрока и свежий HMAC-подписанный `initData`. Compose передаёт тот же `TG_PAT` в настройку `TgMiniAppAuth` backend; отключения auth для development нет. Production build и nginx не включают эмулятор.

## Демо-функции (#92)

`features` в runtime config: `dm`, `friends`, `collection` (по умолчанию false). Индексы вкладок остаются постоянными при скрытии. Флаг mockFeed и генератор демо-ленты удалены.

Содержимое миров находится в `src/api/worldContent.ts`. IT-персонажи — вымышленные адаптации, тексты оригинальные. Лента получает только сохранённые посты игрока и AI-звёзд текущего мира из GET /feed; без backend она пустая. Лента загружается одним GET /feed; каждый пост открывает тред. Детали содержат authorId: под постом звезды можно начать корневой комментарий автору, под своим — ответить на реплику звезды. Флагов разрешений нет. В mock mode игрок и публикации канала сохраняются в localStorage.

Шаг `01-4b_world_setup` предшествует выбору звезды. После POST /onboarding вызывается PATCH /settings. При ошибке настроек повтор не создаёт игрока заново. Для макетов можно использовать `?screen=01-4_channel&world=it`. Кэш экранов сохраняет уже загруженные данные при возврате. Приглашения и шэринг получают персональный код через GET /referral, кэш разделён по PlayerId. Telegram start_param сохраняется в sessionStorage до успешного POST /onboarding (referralCode); при недоступном storage есть fallback в памяти. Первый источник сохраняется, после создания код очищается. Кнопки отправки и копирования заблокированы до загрузки ссылки; при ошибке доступен повтор.

Проверка #92: сборка TypeScript/Vite; браузерный проход Сцены, Академии и IT; сохранение голоса/драмы; повтор settings после ошибки без дублирования onboarding; серверная лента без демо-постов и локальных демо-комментариев; пустая лента без backend; справка навыков; положительный/отрицательный итог и публикация в mock mode. Если числовые причины ответа API не суммируются в итог, карточка показывает их текст без ошибочного разложения прироста.

Шаблоны миров, их правила и каталог звёзд приходят из `GET /worlds/templates`; данные мира игрока — из `GET /worlds/{worldId}`.

### DEV: компактные настройки и первые ходы

Расширенный редактор показывает один экран с раскрываемыми разделами; все поля существующего payload сохраняются. Роли объясняются как занятия персонажа, коллекция — как оформление достижений, голос — как стиль подсказок. Возрастное пояснение использует сохранённую возрастную группу; серверные ограничения не меняются.

Первый пост получает отдельную завязку и действие. В редакторе поста идеи и задания свёрнуты. Промежуточные просмотры заменены статусом реакции, итог показывает прирост и одну причину, полный разбор доступен отдельно. Длинные записи и комментарии раскрываются кнопкой. Подсказка первого ответа закрывается пользователем и запоминается на устройстве для его профиля; переход в ленту доступен отдельно.

### Telegram SDK и зависимости (#168)

Прямой пакет `@tma.js/sdk` закреплён на стабильной версии 3.3.0; React-обёртка не нужна, поскольку интерфейс использует методы SDK без React-хуков. Приложение и DEV-плагин импортируют один и тот же SDK, чтобы `mockTelegramEnv`, `initData` и события кнопок разделяли состояние. В production эмулятор отсутствует.

При миграции учтены `miniApp.setBgColor`, `viewport.expand` и `miniApp.close`. Возвращаемое значение `.ifAvailable()` теперь объект; используемые вызовы не разбирают прежний tuple. Сырые подписанные `initData` продолжают передаваться в API без преобразования ключей. Руководства: [SDK](https://docs.telegram-mini-apps.com/packages/legacy/tma-js-sdk/migrate-from-telegram-apps), [bridge](https://docs.telegram-mini-apps.com/packages/legacy/tma-js-bridge/migrate-from-telegram-apps).

Срез `.npmrc before=2026-10-13` выбран 20.10.2026 с запасом не менее семи дней. Lockfile использует исправленные `valibot@1.5.0` (SDK) и `source-map-js@1.2.2` (PostCSS/Vite). Для проверки: `npm ci`, `npm audit`, `npx tsc -b`, `npm run build`, `node --test tests/*.test.mjs`. После изменения lockfile в DEV нужно выполнить `npm ci` также в контейнере с существующим томом node_modules и перезапустить frontend: пересборка образа не обновляет этот том.

### Генерируемый API-клиент (#122)

`openapi/reki-api.json` — сохранённый результат штатной backend-сборки. Его не редактируют
вручную. Сборке фронтенда нужны только Node/npm и этот снимок: запущенный API, .NET и
секреты не нужны. `npm ci` также устанавливает отдельный toolchain в `tools/api-generator`;
`npm run dev` и `npm run build` сначала запускают генерацию. Ошибка генерации останавливает
запуск/сборку. Programmatic runner проверяет результат генерации и перед запуском удаляет
старый клиент: CLI версии 0.99.0 возвращает успешный код при некоторых ошибках входа.
Тесты проверяют успешную генерацию, отсутствующий/повреждённый контракт и удаление старых файлов.
`src/api/generated/` игнорируется Git и не редактируется вручную.

```sh
npm ci
npm run api:generate
npx tsc -b
npm run build
node --test tests/*.test.mjs
npm audit
npm audit --prefix tools/api-generator
```

Конфигурация генератора: `tools/api-generator/openapi-ts.config.mjs`. Закреплены
`@hey-api/openapi-ts@0.99.0` (22.06.2026) и его компилятор `typescript@6.0.3` (16.04.2026).
Toolchain отделён от TypeScript 7 приложения: генератор использует compiler API, которого
нет в native-пакете TypeScript 7. Оба lockfile и обе `.npmrc` входят в репозиторий.
Toolchain override `js-yaml@4.3.2` (26.08.2026) устраняет известные DoS-уязвимости 4.1.1,
закреплённой транзитивным ref-parser; production-зависимости приложения override не затрагивает.
Прямой `valibot@1.5.0` используется сгенерированными проверками SSE и ошибок публикации.
Даты релизов старше семи дней; срез `before=2026-10-13` сохранён.

После изменения backend-контракта выполнить команды обновления снимка из
[backend/README.md](../backend/README.md#frontend-openapi-contract-122), затем команды выше.
Backend CI сверяет свежий OpenAPI со снимком и собирает фронтенд также при backend-only diff.
Порядок подключения PR: сначала backend metadata + снимок/CI, затем зависимый frontend PR.
Ни JWT из #123, ни будущий ML-протокол #193 эта миграция не вводит.

`src/api/client.ts` сохраняет объект `api` и mock-режим; REST-методы и wire-типы берутся
из генерации. `types.ts` содержит производные модели UI/демо, `mappers.ts` преобразует
числа и проверяет ограниченные UI-значения. `transport.ts` сохраняет runtime base URL,
Telegram Authorization, `ApiError`, журналирование и отсечение запоздавших ответов после
удаления аккаунта. Пустой HTTP 200 у `/challenges/active` нормализуется в `null` перед
JSON-декодированием. Аналитика/логи используют generated SDK с `keepalive`; отдельный
клиент не допускает рекурсивной отправки ошибок телеметрии.

SSE остаётся отдельным обработчиком с generated request types и Valibot-схемами событий.
Встроенный reconnect генератора для POST не используется: публикация/ответ отправляются
один раз, при потере потока проверяется сохранённый статус/пост. AbortSignal, requestId,
publicationId и защита от повторной публикации сохранены.

Docker копирует манифесты обоих toolchain до `npm ci`; build генерирует клиент из снимка.
На DEV с постоянным `node_modules` после обновления манифестов выполнить `npm ci` в
frontend-контейнере и перезапустить его.
