# Frontend v7 — перенос дизайн-системы и границы API (#205)

## Реализация

Frontend использует мобильную дизайн-систему переданного v7: TT Norms Compact/Condensed, theme.css, UI, иконки, социальные действия, профиль и оболочку. Прикладная интеграция — `frontend/src/v7/BackendApp.tsx`; старый API-клиент и сгенерированные DTO не меняются. Дополнительных runtime-зависимостей нет. Возвращающийся игрок начинает с каталога; история выбирается по конкретному worldId.

Реальные серверные операции: каталог/сохранённые миры, обязательная регистрация (14+, обращение), создание истории с ролью, лента с пагинацией, двухэтапная публикация, восстановление статуса, ответы на NPC. Навыки, подписчики и энергия берутся с сервера. Поиск/жанры — локальный фильтр загруженных пресетов.

Исходный автономный прототип доступен только в DEV через `?v7demo`, библиотека — `#system`. Это отдельный сценарный просмотр, а не fallback при ошибке API. Production-сборка не включает DemoApp. Изображения миров сопоставлены существующим серверным пресетам; названия и сценарии четырёх демо-миров не выдаются за существующий серверный контент.

## Надёжность

Сохранённая публикация проверяется с исходным UUID, текстом, OwnWords и WantId; новая отправка не передаёт снятый WantId. Незавершённая отправка блокирует смену мира. Результат и списание подтверждает сервер. Ответ сохраняет RequestId и цель при повторе. Неудачное обновление ленты после подтверждения не превращает успешную публикацию в ошибку отправки. Черновики разделены по аккаунту/экземпляру истории; локальные активности содержат worldId.

Проверки: TypeScript + Vite build; 3 теста подготовки/восстановления публикации; 4 теста mapping реальных форматов ленты, автора треда и дат. В живом DEV API подтверждены каталог, сохранённая история, лента и получение деталей постов. Полный визуальный проход и создание/публикация/ответ ещё требуют проверки, до этого полный parity и готовность к production не заявляются.
