# ML-оценки и отписки — спецификация для #245

#244 подготавливает Compose, клиентов и [balance-new.json](config/balance-new.json). Публикация пока ими не пользуется; действующий `balance.json` не меняется. Хранение векторов, индексы, миграции и backfill будут пересмотрены отдельно в #245.

## Запуск моделей

Штатный Infinity хостит четыре модели: первые три через torch, NLI через optimum. Готовый FP32 ONNX опубликован в приватном [Stepami/rubert-tiny-bilingual-nli-onnx](https://huggingface.co/Stepami/rubert-tiny-bilingual-nli-onnx); это экспорт исходного cointegrated checkpoint без дообучения. Для загрузки нужен HF_TOKEN с правом чтения, заданный вне Git. В контейнере нет пользовательского entrypoint и экспорта при запуске; `--onnx-disable-optimize` оставляет скачанный граф без дополнительной преобразованной копии.

HF_HOME Infinity — `/models-cache`, volume — `infinity-models`. Backend подключает его read-only в `/models` и читает стандартный HF cache: `hub/models--Stepami--rubert-tiny-bilingual-nli-onnx/snapshots/<revision>/model.onnx` и `vocab.txt`. Revision одинаков в настройке модели Infinity и путях backend; он закреплён в Compose. Backend ждёт healthy Infinity, поэтому файлы доступны до его запуска. Модели не попадают в репозиторий; папок `ml/`, `infinity/` и ручного Python-запуска нет. Первый запуск требует интернета; удаление volume удаляет кэш. Backend использует локальный ONNX для правильных NLI-пар, а не строковый `/classify` четвёртой модели.

## Контракты

| Контракт backend | Модель | Результат |
|---|---|---|
| `IEmbeddingGenerator<string, Embedding<float>>`, OpenAI-клиент Infinity | `cointegrated/rubert-tiny2` | Нормированный CLS, 312 измерений, без префикса |
| `ITextSignalsScorer`, `/classify` Infinity | `cointegrated/rubert-tiny-toxicity` | Независимые non-toxic, insult, obscenity, threat, dangerous |
| Тот же scorer | `cointegrated/rubert-tiny2-cedr-emotion-detection` | Независимые no_emotion, joy, sadness, surprise, fear, anger |
| `INliScorer`, ONNX из общего HF cache | `Stepami/rubert-tiny-bilingual-nli-onnx` — экспорт `cointegrated/rubert-tiny-bilingual-nli` | Entailment и not_entailment каждой пары |

NLI принимает premise и список hypotheses с настоящими парными input_ids/attention_mask/token_type_ids. Строковый `/classify` Infinity не сохраняет сегменты пары, поэтому NLI работает в существующем backend. Not_entailment не означает доказанное противоречие. Клиент ограничивает пару 512 токенами, гипотезу 254, остаток получает premise; возвращает результат каждой пары без скрытого агрегирования окон. Обработка длинных постов без потери важных фактов — #245. Клиенты не принимают игровых решений и не обращаются в Mongo.

## Четыре причины

1. `angry_abuse`: агрессивная ругань — min(insult, anger) собственной речи без явно оформленных цитат. Злая критика без оскорблений не равна ругани.
2. `near_copy`: очень близкий собственный повтор в том же мире. Одновременно нужны cosine, NLI в обе стороны и совпадение последовательности числовых токенов. Проверять всех близких кандидатов; первая публикация не повтор. Загрузка истории и хранение векторов — #245.
3. `sad_tone`: выраженная грусть полного текста.
4. `anxious_tone`: выраженный страх/тревога полного текста.

По согласованию пользователя искренняя грустная новость, просьба поддержки и эмоция персонажа могут отталкивать аудиторию. Это эмоциональная окраска, не детектор нытья, виновности или обмана. Цитаты для эмоций сохраняются. Реклама, слабая связь с темой и «воздуханство» не отдельные причины.

Приоритет: ругань → повтор → большая из прошедших порог эмоций (при равенстве грусть). Одна причина, один минус. Смелость/юмор не отменяют причину; счётчика серии нет. Ошибка ML не считается отсутствием причины.

## Пороги и размер потери

Источник чисел — `balance-new.json:unsubscribe`. При средней драме:

| Сложность | Ругань | Повтор cosine / NLI | Грусть / тревога | Доля обычного прироста | Предел аудитории |
|---|---:|---:|---:|---:|---:|
| easy | .80 | .96 / .92 | .96 / .94 | 8% | 0.5% |
| normal | .70 | .94 / .87 | .94 / .92 | 12% | 1% |
| hard | .60 | .92 / .82 | .92 / .90 | 16% | 1.5% |

Базовые пороги JSON заданы для off. Драма off/soft/mid/hot даёт 0/1/2/3 шага: из базового порога вычитается число шагов × соответствующий threshold_reduction_per_step. Размер потери и предел умножаются на loss_multiplier: .5/.75/1/1.25. Повышение сложности и драмы снижает пороги и увеличивает минус; на малом корпусе соседние уровни могут дать одинаковую частоту. Сравнение scores через >=.

При S — аудитории до поста, G — обычном приросте до множителя залёта, a/c — доле прироста/пределе для сложности, m — множителе драмы:

```text
loss = min(S, max(1, round(G*a*m)), max(1, floor(S*c*m)))
delta = -loss
```

Округление к ближайшему чётному. Минимум 1 может превышать процент для малого канала; при S=0 потеря 0. Опыт растёт как прежде. При причине нет обычного прироста и залёта. Без причины сохраняются прежние положительный расчёт и вероятность залёта; драма обычный прирост не уменьшает. Случайный flop заменяется, не добавляется поверх ML.

Числа — стартовый игровой выбор, не вероятности правоты модели. При допущении 10% целевых примеров симуляция 200 seed × 180 дней дала среднему игроку normal+mid 1M на день 51 вместо 53. При 40–60% целевых постов рост существенно медленнее из-за утраченного положительного прироста. Это допущения, не статистика игроков.
