Версия `review-2026-10-20.6`. Предлагаемая сюжетная часть #192; #195 — исторический контент, не реализованный социальный движок. [Автоматы](stories.md) · [Прокачка](progression.md) · [Контекст](knowledge.md)

## Границы фактов

ROOT/CHILD доказывает разговор с конкретным героем. PUB доказывает публикацию. Они не доказывают поддержку, честность, предательство, любовь или намерение примирить. Ответ на спорный пост может быть возражением. Поэтому в текущих автоматах нет договора об «одобряемом» тексте, классификатора намерений и наказания за отсутствие ответа.

Первая цель социального слоя — помнить участие и готовность собеседников, показывать разные следующие обращения. Сильные статусы отношений допускаются только по отдельным однозначным фактам. Это разделяет заполненный текущий этап и ещё не решённые механики, а не маскирует вторые словом «доверие».

## Данные

| Запись | Поля и смысл |
| --- | --- |
| Контакт P ↔ NPC | WorldId, оба actor_id, operation_id, post_id, parent_id, seq, STORY/FREE, episode_id. Записывается один раз после успешной операции. Новая корневая ветка не обязательно новый собеседник. |
| Готовность NPC → P | NORMAL, RESERVED, CLOSED; policy_id/version; основание — NPC-decision/event ID. Это желание участвовать в текущем обсуждении, не числовой Relation и не чувство игрока. |
| Отношение и доверие | Для каждого направления: ACQUAINTED/WARM/FRIEND/DEVOTED/RIVAL/ENEMY/HATE; UNTESTED/WORKING/DAMAGED/REBUILDING/BROKEN. Пока нет надёжного события, сильные значения не назначаются автоматически. |
| Память | Конкретные контакты, приглашения/отказы NPC, capability_used, открытые факты, отдельные обсуждения и исправления NPC. Нельзя хранить вывод «P предал» из свободного текста. |
| Спор NPC ↔ NPC | WorldId, topic_id, actor_A/B, version, seed_ids, state, отдельные decision_A/B, причины и seq. Состояние конкретного спора не равно всей истории отношений. |
| Романтика | NONE/INTEREST/MUTUAL/PARTNER/SEPARATED, совместимость и согласия каждого участника с event_id. Никакого присвоения чувств игроку. |

P — реальный автор игрока, а выбранный герой — его роль. Запись пары не создаёт дубликата NPC. Удаление аккаунта и мира удаляет данные штатно. Старт/повтор эпизода не обнуляет память. Каноническая знакомость остаётся контекстом и не выдаёт новое игровое достижение или статус.

## Что считается готовностью к разговору

По умолчанию новый собеседник NORMAL. У NPC свой policy_id; уровень навыка не заменяет эту политику. На CHECK_READY берутся актуальные версии готовности, спора и контакты текущего запуска. В RESERVED нужны два разных адресных оплаченных контакта в разных post_id текущего мира после последнего собственного приглашения NPC; иначе SEPARATE. Это предложенное условие повторного знакомства, не награда за спам. Сама переписка без такого приглашения CLOSED не снимает.

| Политика | TALK | SEPARATE |
| --- | --- | --- |
| OPEN | Готовность NORMAL; либо RESERVED и выполнено условие двух контактов. Для общего разговора pair_state не FEUD. | CLOSED, невыполненное условие RESERVED либо FEUD. |
| CAUTIOUS | Условия OPEN и хотя бы один адресный контакт с этим NPC в текущем запуске; pair_state не HOSTILITY/FEUD. | Любое отрицание guard TALK. |
| GRUDGE | Условия CAUTIOUS и нет unresolved_correction_id этого NPC по текущему topic_id. | Любое отрицание guard TALK; объяснение ссылается на известное противоречие/отказ, не обвиняет P в нераспознанном поступке. |

Политика контактов текущего этапа: OPEN — isabella, gosha, georgina, roman, jon; CAUTIOUS — eduard, yakov, james, 2kotleti_news, alexey_nl; GRUDGE — diana, greedy_wolf. В конкретном споре policy_A/B из паспорта может быть мягче для согласия на формат разговора: это не пересмотр личного доверия. Проверяются оба уровня: личная готовность каждого и его policy_A/B к данному спору. decision_i = TALK только если обе политики допускают TALK и pair_state входит в NONE/DISPUTE/RIVALRY/DIALOGUE/TRUCE. Для NONE сначала нужны оба seed, создающие DISPUTE; при TRUCE разговор разрешён, но достигнутое перемирие сохраняется. HOSTILITY/FEUD требуют отдельной сцены восстановления; в текущих вступлениях дают SEPARATE. Версии закрепляются при решении.

Новая NPC-возможность по навыку использует личную политику и уже принятые контакты; если NPC отказывается, offer не создаётся и основной сюжет продолжается. В текущих карточках нет автоматических переходов NORMAL → CLOSED от количества ответов, недостатка навыка, паузы или смысла текста.

Изменить готовность можно только собственным событием NPC, например PREPARED_INVITATION → NORMAL, NPC_LIMIT_CONTACT → RESERVED, NPC_CLOSE_TOPIC → CLOSED. Автор, topic_id, причина, публикация и версия обязательны. Простое TALK не снимает старую личную вражду; CLOSED не превращается в HATE. Для свободной генерации таких enum сейчас нет: обычная реплика не становится им задним числом.

## Семь заполненных споров

Открытие спора требует двух подготовленных позиций от указанных NPC, связанных topic_id. Данные первой сцены создают DISPUTE только если записи ещё нет; уже сохранённые HOSTILITY/FEUD и другие состояния не сбрасываются. Обычный пост третьего автора конфликт не создаёт. Правило не выводит противоречие из текста — редактор явно задаёт разные позиции NPC для текущей ситуации.

### Переходы спора

| Из | Факт и точный guard | В | Что увидит игрок |
| --- | --- | --- | --- |
| NONE | Оба NPC сохранили подготовленные разные позиции этого topic_id; запись отсутствует | DISPUTE | Два собственных NPC-высказывания с разными позициями. |
| DISPUTE/RIVALRY/DIALOGUE/TRUCE | Выполнены требуемые контакты карточки; P создал указанную общую тему; оба вычисленных решения TALK и оба опубликованы | DIALOGUE (TRUCE остаётся TRUCE) | Каждый сам пишет, что готов обсуждать здесь. Позиции могут оставаться противоположными. |
| Любое | Хотя бы одно решение SEPARATE; опубликованы решения обеих сторон | То же | Отказавший объясняет дистанцию. Нет объявления о мире или поражении игрока. |
| DIALOGUE | Два отдельных явных NPC_TRUCE по одной теме, оба с сохранёнными собственными публикациями и допустимой предыдущей версией | TRUCE | Оба прямо прекращают публичную перепалку по этой теме. |
| TRUCE/DIALOGUE | Новый подготовленный NPC_DISAGREEMENT по новой конкретной причине и публикации | RIVALRY | Спор возобновился по другому поводу; прошлое перемирие не удаляется. |
| DISPUTE/RIVALRY | Подготовленный NPC_REPUDIATE другого NPC с явно заданной причиной и собственным постом | HOSTILITY | Один герой сам отказывается от сотрудничества. Это не результат угадывания тона. |
| HOSTILITY | Новый NPC_REPUDIATE по новому event_id и новому reason_id того же спора/topic_id, после первого сохранённого отречения | FEUD | Новая явная враждебная сцена с памятью предыдущей; повтор запроса не подходит. |
| HOSTILITY/FEUD | NPC_CORRECTION устраняет заданное противоречие claim_id/value; оба отдельно NPC_REOPEN; все факты после закрытия | RIVALRY | Герои исправили известную запись и снова согласились спорить без прежнего отказа. |
| Любое | Пауза, невмешательство, другой мир, повтор или случайная реплика | То же | Нет скрытой эскалации по таймеру. |

В текущих семи вступлениях заполнены переходы в DISPUTE и DIALOGUE либо сохранение прежнего состояния при отказе. Сцены TRUCE/нового отречения/исправления здесь ещё не написаны: таблица задаёт контракт для следующих глав, не обещает их наличие. Исполнитель не генерирует их произвольно. Для них нужны конкретные опубликованные основания и содержимое новых карточек.

Игрок может отвечать одной стороне, обеим, вести тему в своём канале или не участвовать. Односторонний контакт остаётся односторонним вниманием, не «стороной игрока». Участие в обоих разговорах и публикация общей темы дают возможность двум NPC решить, продолжать ли вместе. Назвать это успешной медиацией можно только при двух явных NPC_TRUCE; текущий DIALOGUE — открытие разговора, не примирение.

## Дружба, вражда и восстановление

Сотрудничество текущего этапа — конкретный общий разговор. Для NPC ↔ NPC можно расширять отношения следующими однозначными событиями. Они требуют заранее заполненной сцены, а не любого ответа P.

| Событие | Условия | Результат |
| --- | --- | --- |
| NPC_MUTUAL_FRIENDSHIP | Две собственные декларации дружбы по общему scene_id, каждый NPC может отказаться | FRIEND/WORKING в обоих направлениях. |
| NPC_REAFFIRM_ALLIANCE | Новый совместный поступок с двумя подтверждениями после сохранённой дружбы | DEVOTED/WORKING; не повтор старой декларации. |
| NPC_PUBLIC_RIVALRY | Собственное явное объявление соперничества; другой actor указан | RIVAL, доверие не обнуляется. |
| NPC_REPUDIATE | Совпадает с подтверждённым HOSTILITY по конкретной причине | ENEMY/DAMAGED в направлении объявившего. |
| NPC_REPEAT_REPUDIATE | Подтверждённый FEUD с новым основанием | HATE/BROKEN; без переноса чувства на P. |
| NPC_CORRECTION + NPC_REOPEN | Известный спорный факт исправлен автором; собственное согласие вернуться | RIVAL/REBUILDING; память сохраняется, дружба не возвращается автоматически. |

Для P ↔ NPC личная дружба, преданность, предательство и чувства P не вычисляются из количества комментариев. Нужен отдельный однозначный факт волеизъявления игрока; текущий интерфейс его не даёт. Поэтому основные 16 автоматов меняют контакты, доступные обращения и наблюдаемую готовность NPC, а не назначают P друга/врага за нераспознанный текст. Восстановление сильного доверия P ↔ NPC также остаётся продуктовым вопросом, без выдуманного «вернуть авторство» в обычной публикации.

## Романтические линии

Сохраняется ранее согласованное: разнополые герои могут выбрать дружбу или добровольную взаимную романтику; однополые линии — дружба/конфликт без романтики. Пол вымышленного готового героя задан паспортом, у собственного персонажа не угадывается по нику/аватару/Telegram. Без заданной совместимости — FRIEND_ONLY. Поддержка, высокий навык, +3 Relation, общая тема и повторные ответы не означают согласие на роман.

Для готовых героев текущих контекстов допустимая будущая пара — isabella ↔ eduard. Яков в первом фильме ещё человек, будущая романтическая линия не переносится; ранняя школа FRIEND_ONLY. diana ↔ jon не допускается из-за родства (редакторский guard, не знание героев), diana ↔ james без выбранной романтической линии; IT-пары однополые. Для собственного героя возможна будущая совместимая разнополая линия при явных данных, отсутствии родства и другого PARTNER. Миграция описаний не должна её включать автоматически.

NONE → INTEREST требует явного интереса участника; MUTUAL — двух отдельных согласий; PARTNER — двух новых подтверждений с проверкой совместимости и отсутствия другой пары атомарно по обоим actor_id. Отказ возвращает NONE без ухудшения дружбы. Разрыв SEPARATED не считается предательством сам по себе. Восстановление пары требует новых согласий. Запись «люблю» в свободном тексте не создаёт этих фактов. Способ надёжного согласия игрока без обязательных карточек ещё не выбран, поэтому эта линия в текущих автоматах не запускается.

## Реализация и проверки

Нужны версионируемые политика/пара/тема, журнал NPC-решений и контактов, сохранённые авторы/якоря, idempotency и доступ по владельцу мира. Два решения и результат сохраняются согласованно; нельзя объявить DIALOGUE до второго согласия. Политика читается перед генерацией и перед коммитом; stale версия откатывает всё без списания. Существующий числовой Relation и его дневной расчёт не меняются. Перед runtime нужны проверки гонок, прав, удаления якоря и воспроизведения событий; продуктовые вопросы согласуются до реализации сильных статусов.
