# Изменение правила

Хвосты остаются почти всегда в одних и тех же местах: описания экранов, исходники экранов, тестовые данные фронта, тела issues. Поэтому идём по списку целиком, даже если правка «маленькая».

1. **Найти все упоминания** старого значения Python-скриптом по `docs/`, `frontend/src`, `.agents/`, телам открытых issues (`gh issue view N --json body`). Сначала проверить, что поиск видит заведомо существующую фразу.
2. **Источник правды:** `docs/game-flow.md` и ключ в `docs/config/balance.json`. Если меняется решение команды, записать «Решено <дата>: …, потому что …».
3. **Спеки:** `docs/backend-spec.md`, при событиях `docs/analytics.md` и `docs/dashboards.md`.
4. **Экраны:** новый `docs/design/src/journey_vN.py` (подключить в конце `build_journey.py`), `python3 docs/design/src/build_journey.py <коды>`, посмотреть PNG; строки в `docs/screens/README.md`.
5. **Фронт:** тексты в `frontend/src/screens`, данные в `frontend/src/api/mock.ts`, типы при изменении API. Мир игрока через `worldOf(player.world)`, не руками.
6. **Issues:** правка в разделе Implementation или Acceptance criteria нужной задачи, не дописывать в конец.
7. **Проверка:** повторить поиск из шага 1 (ноль старых значений вне исторических слоёв `journey_v3…`), `repo-consistency-check` по затронутым числам, `check-secrets --all`, сборка фронта.
8. PR со списком всех мест, где поменялось.
