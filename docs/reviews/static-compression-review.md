# Сжатие статических ответов — отдельное серверное ревью

Связано с #172 и фронтовым PR #174, выложенным в production 0.2.37. По согласованию с пользователем серверная настройка идет отдельным PR на ревью Stepami. Не применять к общей среде и не мержить до его одобрения.

## Зачем игроку

На production стартовый JS передавался без HTTP-сжатия. Даже после уменьшения стартового файла остается примерно 465 КБ raw; gzip-оценка около 141 КБ. Сжатие сокращает сетевую передачу без ухудшения графики и без изменения клиентской логики. Это оценка размера, не гарантия фиксированного времени открытия.

## Изменение

В frontend/nginx.conf включен динамический gzip уровня 6 для HTML (стандартный тип nginx), JS, CSS, JSON-статики и SVG размером от 1024 байт. `Vary: Accept-Encoding` разделяет варианты для кешей; клиент без gzip получает прежний файл. WebP/JPEG уже сжаты и сюда не включены. Cache-Control immutable статики и no-store runtime config сохранены.

В location /api/v1/ gzip явно отключен. JSON API, публикации и SSE остаются на прежнем пути; proxy_buffering off и таймауты не меняются. API, серверная логика и БД не меняются.

## Проверка

Изолированная проверка nginx -t, gzip/identity JS и CSS, Vary, Cache-Control, отсутствия сжатия API и сохранения no-store уже прошла: https://github.com/Stepami/golden-mouth/actions/runs/38605157762. По замечанию Stepami добавленные workflow и скрипт удалены; отдельная CI-инфраструктура не входит в итоговый PR.

После одобрения и выкладки: проверить настоящие production JS/CSS с Accept-Encoding gzip и identity, сравнить распакованный файл с исходным, проверить SSE и сохранить измеренные размеры в #172. До одобрения production gzip не включать.

## Откат

Вернуть предыдущие директивы frontend/nginx.conf и развернуть предыдущую проверенную версию. Статические файлы и API не требуют преобразований данных.
