# Миры и баланс: миграция 2.5.0 (#215)

WorldId использует Guid, BSON UUID Standard subtype 4; JSON — UUID D.
TemplateId имеет тип WorldId? и ссылается на исходный шаблон. У шаблонов и собственных миров он null.
Шаблон: нулевой Player.PlayerId AND TemplateId=null. Каталог дополнительно исключает IsArchived=true.
Difficulty хранится один раз на World. API и balance.difficulties используют easy/normal/hard; BSON использует стандартный EnumSerializer драйвера со строковыми именами Easy/Normal/Hard.
BalanceKey и Interface.Difficulty удалены. Создание с нуля проверяет прежний HitOwnWorldMilestone.

## Преобразование

1. Остановить запись и фоновые исполнители, создать резервную копию. Не запускать старую и новую версии на одной несовместимой схеме.
2. Штатный мигратор выполняет 2.5.0 в одной транзакции. Сопоставления ID живут только в памяти, коллекция соответствий не создаётся.
3. Прочитать worlds/world_templates как BSON. Строковые GUID сохраняют значение; символьные ID шаблонов получают UUID из таблицы. Для ранних составных ID экземпляров берутся первые 16 байтов SHA-256 от UTF-8 строки `reki:world:2.5.0:<старый ID>` с преобразованием через Guid(byte[]). Проверить коллизии до записи.
4. Перенести шаблоны и восстановить отсутствующие старые записи из SeedWorldTemplates.CreateTemplates. Существующий актуальный контент не заменять seed-версией. Старые stage/academy/stream/own архивируются; it остаётся доступным.
5. Перенести экземпляры. TemplateId восстановить из старого BalanceKey; для own он null. Сложность восстановить из механического профиля, игнорируя старую декоративную подпись. Все старые own получают normal.
6. Снимки сложности и коэффициентов в публикациях не создавать; если осталось поле BalanceSnapshot от промежуточной версии, удалить его. Незавершённые публикации подтверждаются по текущей сложности мира и актуальному балансу, включая старый own → normal.
7. Переписать ссылки в posts, publications (включая вложенный результат), events. Удалить все существующие записи GenerateStarFeedPostJob из ticker_TimeTickers независимо от статуса: старые одноразовые задания не поддерживаются, их payload не преобразуется. Это включает историю заданий для удалённых миров и игроков. Остальные одноразовые задания и cron-расписания сохранить. RequestHash публикаций привести к каноническому UUID D, сохранив текст и остальные входные параметры. Опубликованные результаты не пересчитывать.
8. Удалить BalanceKey и Interface.Difficulty. Сохранить остальные поля документов и индексы. Неизменяемый MongoDB _id заменяется удалением/вставкой в транзакции. Отсутствующие цели ссылок и коллизии приводят к отказу транзакции.
9. После успешных проверок запустить только совместимые версии API, фронта и фоновых исполнителей. При ошибке транзакция откатывается; повтор использует те же UUID. Для отката релиза восстановить согласованные версии приложения и БД из резервной копии.

## Публикации и локальные данные

При подтверждении незавершённой публикации расчёт и допуск хейта используют текущую Difficulty мира и актуальный баланс. Смена сложности до подтверждения или рестарт не сохраняют прежние коэффициенты. Drama, safety cooldown, владение и ресурсы повторно проверяются. Уже завершённая публикация при replay возвращает сохранённый результат без пересчёта.

Фронт использует новые ключи локального хранения v2 для выбранного мира и черновиков. Старые данные сбрасываются: миграции и совместимости локальных черновиков нет. UUID игроку не показывается.


## Проверка выпуска

- Полный прогон истории на пустой изолированной БД и обновление существующих документов до 2.5.0.
- Старые задания генерации ленты, включая завершённые записи с отсутствующим миром, удалены; остальные задания и cron-расписания сохранены.
- Повтор 2.5.0 без дублей, смены UUID, потери прогресса и ссылок; отсутствие коллекции соответствий.
- Архивные шаблоны скрыты из каталога создания, старые экземпляры работают.
- Генерация при easy, смена на hard, подтверждение при hard; повтор завершённой публикации возвращает тот же результат без пересчёта.
- Для own, начатого до миграции, незавершённая публикация подтверждается по normal; legacy-баланс не сохраняется.
- Build/style/tests, генерация OpenAPI и клиентов, frontend typecheck/build, Docker build/health и secrets scan.

Связанные изменения: [#215](https://github.com/Stepami/golden-mouth/issues/215), [#184](https://github.com/Stepami/golden-mouth/issues/184).

TickerQ остаётся на 10.4.0. Штатный ConfigureJobRetention документирован для ещё не опубликованной в NuGet линейки 10.5.x; автоматическая очистка отложена до её выхода. Самописная задача retention не добавляется.
