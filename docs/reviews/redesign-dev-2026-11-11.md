# Доработка редизайна на DEV — 11.11.2026

Refs #205. После решения вернуть прежний интерфейс на production редизайн проверяем на DEV. Этот пакет меняет frontend, без миграций и изменения backend.

## Что изменено

- Обычный выход вызывает существующий `/auth/logout` и возвращает выбор способа входа. Черновики сохраняются. Очистка API-кэша и смена поколения сессии защищают следующий вход от данных прошлого аккаунта.
- В общем профиле есть «Пригласить друга». Ссылка получается из существующего `/referral`, её можно отправить или скопировать. Текст награды соответствует текущему `AwardReferral`: 3 кристалла за первый пост приглашённого.
- В редакторе доступны три статические подсказки для каждого из четырёх миров. Они не начисляют прогресс и не закрывают задания. Подсказка заменяет непустой черновик после подтверждения; «Очистить пост» очищает его сразу.
- Обложка сохранённого мира определяется также по сценарию, а не только по ID экземпляра или старому названию. При первом входе и повторном открытии используется картинка мира.
- У Бургера и Куляша новые мужские портреты. Портрет Ники сохранён.
- Только свой герой получает конструктор: два мужских и два женских базовых образа. Это локальная сборка подготовленных изображений, без платного запроса генерации на каждое нажатие. Готовые герои сохраняют закреплённую внешность.
- Серия есть в верхней панели мира и в уведомлениях с первого дня. В переданном автономном v7 отдельной серии в шапке нет; в поздней интеграции серия размещена в профиле персонажа.
- Сохранённые ответы NPC добавляются в уведомления, включая ответы после комментария игрока. При открытии вкладки восстанавливаются ответы из доступных публикаций текущего персонажа. Одно событие определяется ID комментария; открывается его исходный пост. Реакции группируются по публикации и используют серверные счётчики.

## Ограничения API для согласования

1. История уведомлений хранится на устройстве. Для синхронизации нужен серверный список событий с ID, временем, типом, адресатом, миром, ссылкой на пост/комментарий, автором и статусом прочтения.
2. В ответе реакций есть emoji и count, но нет списка авторов. Фронт показывает подтверждённое число; имена поставивших лайк не выдумываются. События репоста сервер пока не отдаёт, кнопка цитирования не доказывает репост.
3. `StreakResponse` содержит days, week и nextReward. В текущем коде days задаётся при регистрации; работа ежедневного прироста и выдачи наград не подтверждена этим UI-пакетом. Нет события начисления кристаллов с причиной «серия». Уведомление первого дня подтверждает отметку серии, но не обещает уже начисленную награду. Суммы наград этим пакетом не меняются.
4. Конструктор хранит результат на устройстве, как прежний выбор портрета. Для другого устройства нужен серверный контракт внешности: версия набора, baseId или отдельное хранение загруженного изображения. Поле avatar сейчас используется как имя канала/seed; изображение туда не записываем.
5. Для короткого уникального ника нужен серверный резерв имени и сохранение в аккаунте. Технический ID не сокращаем с обещанием гарантированной уникальности.

### Предложение по уведомлениям о приглашении — требует согласования backend

Существующий GET /invitation возвращает только бонус приглашённого, а не события для пригласившего. Регистрация друга и начисление пригласившему сейчас не создают доступную фронту историю. По изменению общего баланса нельзя надёжно восстановить причину награды.

Предлагаются два подтверждённых события в серверной истории уведомлений:

1. `referral_joined`: друг завершил регистрацию по ссылке. Текст: «Друг присоединился по твоей ссылке». Открытие ссылки само по себе регистрацией не считается.
2. `referral_first_post`: друг опубликовал первый пост; payload содержит фактически начисленное число кристаллов и причину. При подтверждённом начислении 3 текст: «Друг опубликовал первый пост. Тебе начислено 3 кристалла за приглашение». Действующий суточный лимит не обходится, начисление фронтом не имитируется.

Для каждого события нужны стабильный ID, время, получатель и связь с приглашением; повторный запрос не создаёт дубликат. Backend этим пакетом не меняется.

## Ник и удаление прохождения

- Старое отображение `reki_` + UUID заменяется коротким игровым псевдонимом (два слова и короткий суффикс). Старое сохранённое имя сохраняется. Псевдоним детерминирован по ID аккаунта, но не является зарегистрированным сервером уникальным адресом. Полный ID остаётся внутренним идентификатором. Серверное резервирование ника остаётся отдельным согласованием.
- Иконка корзины предусмотрена у каждой записи «Моих миров» в каталоге и общем профиле. Кнопка открывает окно с названием мира и персонажем; операция удаления недоступна до реализации backend. Мир не скрывается локально и не выдаётся ложное сообщение об успешном удалении.
- Предложение backend для согласования: удалять только принадлежащее игроку прохождение по ID экземпляра мира. Каталог шаблонов, другие прохождения и общие энергия/кристаллы сохраняются. Нужно отдельно определить удаление или архивирование связанных постов, комментариев и памяти NPC, а также идемпотентный ответ на повтор. Текущий API не содержит DELETE для одного мира; существующий DeleteWorldsAsync относится к удалению аккаунта целиком.

Корзина добавлена в набор LineIcon и галерею иконок дизайн-системы. В плитке она заменяет стрелку, без отдельной текстовой колонки. Сохраняются прежние ширина карусели и отступы карточки.

### Более компактный вариант редактора

После повторного просмотра: сюжет — одна нейтральная строка с раскрытием полного текста; слот ежедневного челленджа — отдельная строка с приглушённым оттенком токена кристаллов. Статичный вариант без бегущего текста. «Твоя практика» в редакторе занимает одну строку, навыки и рекомендации видны по раскрытию; на остальных экранах компонент не меняется. Подсказки четырёх миров показаны короткими тематическими Chip, по нажатию открывается полный текст с действием «Использовать». Замена непустого черновика по-прежнему требует подтверждения.

Согласованная для дальнейшего подключения пробная лестница ежедневного челленджа: 1, 1, 1, 1, 2, 2, 3 кристалла за семь выполненных ежедневных заданий (11 за цикл). Пропуски не сжигают накопленный шаг; после седьмого выполнения начинается новый цикл. Это предложение будущего серверного контракта, не действующий баланс: активные balance.json, награды существующей серии и backend не менялись. Данные задания, подтверждённый шаг, сумма награды и однократное начисление должны приходить с сервера. Пока в слоте показано «Пока нет задания»; фронт не обещает и не начисляет кристаллы. Следующий исполнитель для контракта ежедневных заданий — Степан.

### Награда в заголовке и готовый первый пост

По указанию владельца продукта награда перенесена в заголовок «Задание на сегодня». Пока live OpenAPI DEV не содержит ежедневного квеста или его суммы, показан значок кристаллов и прочерк; выдуманное начисление не обещается. Полученные данные задачи заменят прочерк числом.

Первый обычный пост автоматически заполняется готовой репликой выбранного героя. Используются тексты firstPost.ts; для других персонажей — серверный demoPosts, затем подсказка мира. Инструкция firstPrompt не вставляется вместо текста поста. Через существующий channelPosts проверяется отсутствие своих публикаций. Подстановка однократная: только при отсутствии сохранённого/очищенного черновика и незавершённой отправки; ответы и цитирование не заполняются. Сохранённый текст помечен ownWords=false, редактирование пользователем сохраняет прежнюю механику собственных слов. Публикация остаётся ручной.

Одноразовой проверкой фактического обработчика openCompose подтверждены заполнение нового канала, сохранность пользовательского текста, отсутствие повторной вставки после очистки, отсутствие подстановки в канал с публикациями и доступность редактора при ошибке API. Автоматической публикации или изменений в общем DEV-аккаунте для проверки не выполнялось.


### Эффект набора первого поста и объяснение награды

Готовая первая реплика при открытии редактора появляется с эффектом набора и мигающим курсором (до 2,52 секунды вместе с начальной паузой). Это только визуальный слой: полная строка остаётся в textarea, хранилище и команде публикации. Фокус в поле мгновенно завершает эффект; редактируемые черновики и ответы не анимируются. Настройка prefers-reduced-motion отключает эффект. При выходе с экрана кадры отменяются.

Отдельный кристалл с прочерком удалён. Под условием задания выводится «Выполни задание — получи» и серверное количество кристаллов; в пустом состоянии — «За выполнение — награда в кристаллах». Число пока не выдумывается. Склонение единицы награды учитывает количество.

Проверены TypeScript/build, secret scan и diff. В отдельном headless Chrome с настоящими React-компонентами и реальным временем подтверждены промежуточный набор (35 из 172 символов), сохранность полного текста, мгновенное завершение при фокусе и отображение связи условия с наградой. Число 1 в изолированной проверке — пример для компонента, не реальные данные или начисление на DEV.


### Пример первого ежедневного задания на DEV

По явному запросу владельца продукта добавлено превью: «Опубликуй первый пост и задай персонажам вопрос», награда 1 кристалл. Включается только в Vite DEV через import.meta.env.DEV и помечено «Превью» в заголовке. Production build не включает демонстрационное задание. Пример служит проверкой вида условия и награды; не меняет баланс, не засчитывает выполнение и не начисляет кристаллы. ### Результат публикации: аудитория и раскрываемые навыки

По референсу владельца продукта уведомление ResultIsland переработано в два состояния. Сначала крупно показывается подтверждённое изменение подписчиков и процент от сохранённой аудитории перед ходом. Рост выделен мятным акцентом, снижение — янтарным; нулевой результат нейтрален. Если исходная аудитория неизвестна или равна нулю, процент не выдумывается. Снимок beforeSubscribers сохраняется для новых постов и комментариев, в том числе для восстановления отправки.

В resultCopy.ts подготовлено по 10 коротких фраз на рост и снижение и отдельная фраза для нуля. Вариант выбирается случайно один раз на результат и сохраняется в receipt.reactionText; повторный рендер или раскрытие не меняют фразу. Формулировки снижения без стыда, угроз и давления. Баланс, рост подписчиков и серверные награды не меняются.

Нажатие на карточку раскрывает вторую часть с тремя навыками. Для доступных снимков до/после показаны изменение прогресса в п.п., переход уровня и шкала текущего уровня через общий Progress. Рост навыка окрашен независимо от направления изменения подписчиков. Неизвестные ролевые значения остаются неизвестными, базовые навыки не переименовываются в ролевые и фиктивный XP не создаётся. Отдельная кнопка «Читать отклики» открывает обсуждение. Раскрытая карточка не закрывается по таймеру; каждый новый actionId начинает со свёрнутого состояния. Галерея VisualReview использует тот же компонент с примерными снимками до/после.

Проверены TypeScript/build, secret scan, diff; расчёты процентов (+16/120, снижение, ноль, малая доля, отсутствующая/нулевая база) и уникальность 10+10 фраз. Настоящие React-компоненты проверены в отдельном headless Chrome: 320/390/430/1280 px, текст 200%, рост/снижение/ноль, большие числа, отсутствие данных навыков, раскрытие без навигации, стабильность фразы и переход к откликам отдельным действием. После перехода на общий Progress отдельно проверены фактические значения шкал. Данные и изображения проверки — синтетические; публикации и начисления в общем DEV-аккаунте не выполнялись.


### Значки навыков, характер фраз и обратная связь результата

В раскрытых результатах у каждого навыка показан общий SkillArt из дизайн-системы. В свёрнутом результате подготовлена краткая строка только для подтверждённых выросших навыков: значок, название, прирост прогресса в п.п.; при повышении уровня — новый уровень и его процент. Неизвестные и неизменившиеся навыки в эту строку не попадают.

По просьбе владельца продукта 10 фраз роста и 10 фраз снижения переписаны в более абсурдном тоне, без упрёков и давления. Старые банальные фразы в сохранённых уведомлениях заменяются новым вариантом при показе; текст остаётся стабильным внутри карточки.

При появлении результата число и процент отсчитываются от нуля. После дополнительного замечания длительность увеличена до 2 секунд с начальной паузой 200 мс, используется плавное замедление. Обновление тех же данных не перезапускает эффект. prefers-reduced-motion показывает итог сразу. В Telegram восстановлен тот же вызов notificationOccurred(success/warning), что в прежнем экране результата. В вебе используется navigator.vibrate при поддержке устройства: короткий двойной импульс, один раз на результат. При отсутствии API ничего не ломается; Safari/iPhone и обычный desktop-браузер могут не выдавать физическую вибрацию.

Проверены реальные React-компоненты в отдельном Chrome: значки трёх навыков, краткая строка только при наличии прироста, её отсутствие без данных, промежуточные значения счётчика, рост и снижение, узкие экраны, текст 200% и reduced motion. Вызовы нативного и веб-отклика проверены перехватом фактического эффекта; физическая вибрация на устройстве этой проверкой не подтверждается.

### Результат ниже статус-бара и сбор кристаллов

Карточка ResultIsland измеряет полную высоту world-hud и располагается на 16 px ниже. ResizeObserver отслеживает border-box шапки и оболочки, учитываются прокрутка и изменение окна; раскрытая часть прокручивается в доступной высоте. После ответа на комментарий статус-бар временно показывается над результатом и там. Обычная навигация закрывает результат.

CrystalRewardBadge показывает прилёт каждого кристалла к значку ресурса, отдельный импульс увеличения значка и поштучный счётчик. Слой частиц вынесен порталом в оболочку выше карточки, включая временный статус-бар комментариев. Источник баланса не меняется: анимация разрешена лишь для подтверждённого server-reward с event/action ID, суммой и снимками balanceBefore/balanceAfter, когда новый кошелёк совпадает с after и разность снимков равна награде. Событие проигрывается один раз; прочие изменения кошелька не выдаются за награду квеста. Старые preview/unmarked награды не пропускаются в живой результат. Реальный ежедневный контракт ещё ожидается от Степана; автоматического парсинга несуществующих полей API не добавлено.

В DEV #result-review добавлена отдельная кнопка «Показать награду: 10 → 13». Она использует локальные демонстрационные данные и не меняет реальный кошелёк. Проверены настоящие React-компоненты в отдельном Chrome: видимый статус-бар, зазор 16 px, 10→11→12→13, три импульса, отсутствие повтора, изменение высоты шапки, 320/390 px, текст 200%, reduced motion (сразу итог, без прилёта).

### Более заметный статус ответа NPC

Для ответа на комментарий и дополнительного отвечающего персонажа статус «Имя печатает» с аватаром и тремя анимированными точками виден минимум 2,4 секунды. Реальная генерация дольше этого срока не получает дополнительную задержку. Свой комментарий появляется сразу. NPC-ответ сохраняется на сервере перед визуальной паузой; остановка ожидания отменяет паузу, не удаляя сохранённый ответ. Повтор генерации тем же персонажем не обнуляет уже прошедшее время; дополнительный персонаж получает собственный отсчёт.

Проверены фактический helper задержки (остаток, отсутствие дополнительной паузы для медленного ответа, отмена), фактический save-helper API (сначала сохранение, затем визуальная пауза и onSaved; собственный комментарий без паузы), TypeScript/build, secret scan и diff. Реальные комментарии и начисления в общем DEV-аккаунте в этих проверках не создавались.

### Временные +2 за ход на DEV и видимый таймер

По явному запросу владельца продукта до подключения backend включено по 2 визуальных кристалла за каждый подтверждённо сохранённый пост или комментарий. Режим только Vite DEV. Локальный ledger devCrystalPreview изолирован по аккаунту, сохраняется в этом браузере и учитывает actionId, поэтому повторная доставка/восстановление того же хода не даёт ещё +2. Уведомление помечает награду «Превью: за ход», индикатор кристаллов — «Превью». Показатель равен серверному кошельку плюс локальная сумма превью. Кошелёк API, обмен, экономика и production не изменяются. При подключении настоящих квестовых наград backend этот временный режим frontend нужно убрать и использовать подтверждённую сумму конкретного задания.

Карточка примера ежедневного задания на DEV теперь предлагает пост или комментарий и показывает 2 кристалла, согласованно с временным режимом. Реальная награда не выдаётся и завершение серверного квеста не имитируется.
