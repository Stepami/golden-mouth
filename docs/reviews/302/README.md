# Frontend лайков — #302

UI для текущей дизайн-системы production: компактная кнопка «♡ 42» на основе существующего класса `.react`, без отдельной подписи. Область нажатия сохраняет высоту 44px. После подтверждения новой отметки сердце пружинит и даёт короткую вспышку; при открытии уже отмеченных постов вспышка не повторяется; при prefers-reduced-motion анимация отключена. Счётчик при личной отметке не увеличивается. Backend остаётся в #301.

`PostLikes` получает подтверждённое число лайков аудитории, состояние личной отметки и callback сохранения. Компонент не считает «речность», не прибавляет личный лайк к счётчику, не читает энергию и не меняет состояние отметки до получения новых данных от вызывающего кода. Сердце доступно с клавиатуры; во время сохранения заблокировано, ошибка позволяет повторить действие.

**Зависимость:** на момент подготовки в #301 нет согласованных DTO и операции сохранения. Generated-клиент, API-фасад, backend и текущие карточки не менялись. Старые emoji не превращены в лайки на frontend. Включение компонента в результат/ленту/канал/тред и сквозное сохранение должны завершиться по настоящему контракту #301. Эта подготовка UI не закрывает #302 и не готова к production.

План размещения: в результате — сразу после прироста аудитории, перед разбором; под постами ленты/канала/треда — вместо строки emoji, рядом с просмотрами и комментариями. Число берётся из ответа API, состояние сердца отдельно. Дополнительно в #302 согласован пункт «Я → Отмеченные посты» для выбранного мира; чтение личного списка нужно в #301. Этот экран пока не реализован в PR.

Проверено на Mini: TypeScript/Vite build, существующие frontend-тесты 12/12. В изолированном Chrome с синтетическим callback проверены нулевая энергия, неизменный счётчик аудитории после отметки/снятия, ожидание подтверждения, двойное нажатие (один callback), ошибка/повтор, клавиатура Space, пружинистый отклик/вспышка после отметки, отсутствие успешной вспышки при ошибке снятия, отключение анимаций при reduced motion, остановка клика карточки и ширины 320/390/430/1280. Props компонента — UI-интерфейс, а не утверждённые DTO backend.

Снимки примеров размещения: [обычный](idle.png), [отмеченный](marked.png), [ожидание](pending.png), [ошибка](error.png), [личная отметка при нулевых лайках аудитории](zero-marked.png). Использованы текущие Card, Avatar и стили результата. Это синтетические примеры компонента, а не подключённые к API игровые экраны.

При подключении экрана экземпляр компонента должен соответствовать игроку/миру/посту; данные всех представлений обновляются из ответа сервера. Сквозные переходы между игровыми экранами, перезагрузка и физический телефон пока не проверены: контракт #301 отсутствует.

## Предложение вкладки профиля

В текущем «Я» под шапкой профиля — существующий Segmented с «Обзор» / «Отмеченные». Обзор сохраняет нынешнее содержимое профиля. Вторая вкладка показывает личные отмеченные посты выбранного мира: автор, текст, заполненное сердце, серверные лайки аудитории и просмотры. Карточка открывает существующий тред; снятие отметки убирает запись из списка после подтверждения.

[Вкладка с постами](profile-marked.png) · [пустой список](profile-empty.png). Это синтетический DEV-пример на текущих Card, Avatar, TopBar и Segmented, а не подключённый к API экран приложения. Проверены переключение вкладок, открытие/возврат, снятие отметок, пустой список и ширины 320/390/430/1280. Реальное чтение списка ждёт контракт #301; в production навигацию не добавляли.
