# Доработка редизайна на DEV — 11.11.2026

Refs #205. После решения вернуть прежний интерфейс на production редизайн проверяем на DEV. Этот пакет меняет frontend, без миграций и изменения backend.

## Что изменено

- Обычный выход вызывает существующий `/auth/logout` и возвращает выбор способа входа. Черновики сохраняются. Очистка API-кэша и смена поколения сессии защищают следующий вход от данных прошлого аккаунта.
- В общем профиле есть «Пригласить друга». Ссылка получается из существующего `/referral`, её можно отправить или скопировать. Текст награды соответствует текущему `AwardReferral`: 3 кристалла за первый пост приглашённого.
- В редакторе доступны три статические подсказки для каждого из четырёх миров. Они не начисляют прогресс и не закрывают задания. Подсказка заменяет непустой черновик после подтверждения; «Очистить пост» очищает его сразу.
- Обложка сохранённого мира определяется также по сценарию, а не только по ID экземпляра или старому названию. При первом входе и повторном открытии используется картинка мира.
- У Бургера и Куляша новые мужские портреты. Портрет Ники сохранён.
- Только свой герой получает конструктор: два мужских и два женских базовых образа. Это локальная сборка подготовленных изображений, без платного запроса генерации на каждое нажатие. Готовые герои сохраняют закреплённую внешность.
- Серия есть в верхней панели мира и в уведомлениях с первого дня. В исходном интерфейсе Ромы она находилась в профиле персонажа, без кнопки в шапке.
- Сохранённые ответы NPC добавляются в уведомления, включая ответы после комментария игрока. При открытии вкладки восстанавливаются ответы из доступных публикаций текущего персонажа. Одно событие определяется ID комментария; открывается его исходный пост. Реакции группируются по публикации и используют серверные счётчики.

## Ограничения API для согласования

1. История уведомлений хранится на устройстве. Для синхронизации нужен серверный список событий с ID, временем, типом, адресатом, миром, ссылкой на пост/комментарий, автором и статусом прочтения.
2. В ответе реакций есть emoji и count, но нет списка авторов. Фронт показывает подтверждённое число; имена поставивших лайк не выдумываются. События репоста сервер пока не отдаёт, кнопка цитирования не доказывает репост.
3. `StreakResponse` содержит days, week и nextReward. В текущем коде days задаётся при регистрации; работа ежедневного прироста и выдачи наград не подтверждена этим UI-пакетом. Нет события начисления кристаллов с причиной «серия». Уведомление первого дня подтверждает отметку серии, но не обещает уже начисленную награду. Суммы наград этим пакетом не меняются.
4. Конструктор хранит результат на устройстве, как прежний выбор портрета. Для другого устройства нужен серверный контракт внешности: версия набора, baseId или отдельное хранение загруженного изображения. Поле avatar сейчас используется как имя канала/seed; изображение туда не записываем.
5. Для короткого уникального ника нужен серверный резерв имени и сохранение в аккаунте. Технический ID не сокращаем с обещанием гарантированной уникальности.

## Проверка

На реальном DEV проверены загрузка ссылки, отдельные портреты, четыре пресета и сборка конструктора, обложки сохранённых миров, очистка и заполнение черновика, первый день серии, ответ NPC после нового поста и logout. Экраны проверяются на мобильной и desktop-ширине. Полный OAuth-вход и объединение двух реальных аккаунтов этой проверкой не выполняются.

### Предложение по уведомлениям о приглашении — требует согласования backend

Существующий GET /invitation возвращает только бонус приглашённого, а не события для пригласившего. Регистрация друга и начисление пригласившему сейчас не создают доступную фронту историю. По изменению общего баланса нельзя надёжно восстановить причину награды.

Предлагаются два подтверждённых события в серверной истории уведомлений:

1. `referral_joined`: друг завершил регистрацию по ссылке. Текст: «Друг присоединился по твоей ссылке». Открытие ссылки само по себе регистрацией не считается.
2. `referral_first_post`: друг опубликовал первый пост; payload содержит фактически начисленное число кристаллов и причину. При подтверждённом начислении 3 текст: «Друг опубликовал первый пост. Тебе начислено 3 кристалла за приглашение». Действующий суточный лимит не обходится, начисление фронтом не имитируется.

Для каждого события нужны стабильный ID, время, получатель и связь с приглашением; повторный запрос не создаёт дубликат. Backend этим пакетом не меняется.

## Ник и удаление прохождения

- Старое отображение `reki_` + UUID заменяется коротким игровым псевдонимом (два слова и короткий суффикс). Старое сохранённое имя сохраняется. Псевдоним детерминирован по ID аккаунта, но не является зарегистрированным сервером уникальным адресом. Полный ID остаётся внутренним идентификатором. Серверное резервирование ника остаётся отдельным согласованием.
- Иконка корзины предусмотрена у каждой записи «Моих миров» в каталоге и общем профиле. Кнопка открывает окно с названием мира и персонажем; операция удаления недоступна до реализации backend. Мир не скрывается локально и не выдаётся ложное сообщение об успешном удалении.
- Предложение backend для согласования: удалять только принадлежащее игроку прохождение по ID экземпляра мира. Каталог шаблонов, другие прохождения и общие энергия/кристаллы сохраняются. Нужно отдельно определить удаление или архивирование связанных постов, комментариев и памяти NPC, а также идемпотентный ответ на повтор. Текущий API не содержит DELETE для одного мира; существующий DeleteWorldsAsync относится к удалению аккаунта целиком.

Корзина добавлена в набор LineIcon и галерею иконок дизайн-системы. В плитке она заменяет стрелку, без отдельной текстовой колонки. Сохраняются прежние ширина карусели и отступы карточки.

### Пробная компоновка редактора с двумя заданиями

По согласованию владельца продукта: над полем публикации две компактные карточки — «По сюжету» с текущим заданием и раскрываемым контекстом, «На сегодня» с местом под ежедневный квест. Для сюжетного задания используются prepared/roleTask; при отсутствии задания показан свободный пост или завершение истории. В API пока нет подтверждённого ежедневного квеста новой механики, поэтому второй блок показывает «Пока нет ежедневного задания», без выдуманного прогресса, наград и условий. Подключение ежедневного квеста зависит от контракта Степана. При ответе на комментарий эти карточки не добавляются.

Подсказки под редактором сохраняют полный текст, но уменьшены до 14 px с отступами 10×12 px. Для заданий используется текст 14 px и метки 12 px; подробности сюжета раскрываются по нажатию. Условия зачёта, публикация и подтверждение замены черновика не изменены.


### Более компактный вариант редактора

После повторного просмотра: сюжет — одна нейтральная строка с раскрытием полного текста; слот ежедневного челленджа — отдельная строка с приглушённым оттенком токена кристаллов. Статичный вариант без бегущего текста. «Твоя практика» в редакторе занимает одну строку, навыки и рекомендации видны по раскрытию; на остальных экранах компонент не меняется. Подсказки четырёх миров показаны короткими тематическими Chip, по нажатию открывается полный текст с действием «Использовать». Замена непустого черновика по-прежнему требует подтверждения.

Согласованная для дальнейшего подключения пробная лестница ежедневного челленджа: 1, 1, 1, 1, 2, 2, 3 кристалла за семь выполненных ежедневных заданий (11 за цикл). Пропуски не сжигают накопленный шаг; после седьмого выполнения начинается новый цикл. Это предложение будущего серверного контракта, не действующий баланс: активные balance.json, награды существующей серии и backend не менялись. Данные задания, подтверждённый шаг, сумма награды и однократное начисление должны приходить с сервера. Пока в слоте показано «Пока нет задания»; фронт не обещает и не начисляет кристаллы. Следующий исполнитель для контракта ежедневных заданий — Степан.

### Один ежедневный квест по референсу

По уточнению владельца продукта: один ежедневный квест над редактором, общий компонент для всех миров. DailyQuestCard принимает текст и количество кристаллов как данные представления; реальные условие, награда и подтверждение зачёта ждут согласованного API Степана. Пока карточка показывает «Новое задание скоро появится», без суммы и имитации начисления. Старые wants не приравниваются к новой механике.

В WorldBrief сохранены общая цель, характеристики и переход к посту. Сюжетные материалы и профиль персонажа сохранены. Подсказки под полем — горизонтальные карточки с полным текстом 14 px и частично видимой соседней карточкой; модального просмотра нет. Подтверждение замены непустого черновика сохраняется.

Проверены TypeScript/build, secret scan, diff и изолированный блок редактора в headless Chrome на 320/390/430/1280 px и при тексте 200%: основной экран не переполняется, горизонтальная прокрутка ограничена подсказками.


### Награда в заголовке и готовый первый пост

По указанию владельца продукта награда перенесена в заголовок «Задание на сегодня». Пока live OpenAPI DEV не содержит ежедневного квеста или его суммы, показан значок кристаллов и прочерк; выдуманное начисление не обещается. Полученные данные задачи заменят прочерк числом.

Первый обычный пост автоматически заполняется готовой репликой выбранного героя. Используются тексты firstPost.ts; для других персонажей — серверный demoPosts, затем подсказка мира. Инструкция firstPrompt не вставляется вместо текста поста. Через существующий channelPosts проверяется отсутствие своих публикаций. Подстановка однократная: только при отсутствии сохранённого/очищенного черновика и незавершённой отправки; ответы и цитирование не заполняются. Сохранённый текст помечен ownWords=false, редактирование пользователем сохраняет прежнюю механику собственных слов. Публикация остаётся ручной.

Одноразовой проверкой фактического обработчика openCompose подтверждены заполнение нового канала, сохранность пользовательского текста, отсутствие повторной вставки после очистки, отсутствие подстановки в канал с публикациями и доступность редактора при ошибке API. Автоматической публикации или изменений в общем DEV-аккаунте для проверки не выполнялось.
