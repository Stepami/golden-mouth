# Настройки, свой мир и приглашение — DEV

Refs #205. По решению владельца продукта 11.11.2026 три функции добавлены в текущую DEV-сборку с возможностью отдельного отката. Контрольная версия до них — `592b547`.

- В профиле персонажа доступна кнопка «Настройки мира». Редактор меняет сложность, драму, общий стиль, сведения о мире и персонаже, состав собеседников, их характеры/стиль и правила. Используется существующий PUT мира; идентификаторы NPC, неизменённые награды и достижения передаются без пересоздания. Сервер сохраняет историю, аудиторию и отношения. Непустые обязательные поля проверяются до отправки; ошибка оставляет заполненную форму.
- «Создать свой мир» открывает ту же полную форму с отдельным персонажем, четырьмя вариантами внешности, начальной ситуацией, правилами и собеседниками. Убран прежний лимит формы на трёх собеседников. Создание выполняет существующий POST, доступ разрешает серверный `hitOwnWorldMilestone`.
- На главной и в общем профиле показан баннер. До разблокировки — условие первого поста друга, награда 3 кристалла, доступ 0/1 и приглашение со ссылкой. После серверного подтверждения — доступ 1/1 и кнопка создания. Это показатель доступа к конструктору, а не выдуманный счётчик зарегистрированных друзей. Существующий backend может открыть конструктор также через прежний порог аудитории; frontend его не меняет. «Проверить доступ» повторно читает серверное состояние. События начисления/регистрации друга не имитируются.

## Откат

Функции разделены на коммиты `restore editable world settings`, `restore full custom world creation` и `restore own world invitation banner`. Чтобы убрать весь пакет, выполнить обычный revert этих коммитов от последнего к первому, сохраняя последующие несвязанные правки. После этого обновить только frontend DEV. Контрольная ветка `codex/205-before-world-controls` указывает на исходный код. Миграций и backend-изменений нет. Изменения мира, которые пользователь уже явно сохранил через редактор, являются пользовательскими данными и не отменяются откатом интерфейса.

## Проверка

TypeScript/build, secret scan и diff --check. Настоящий BackendApp проверен в отдельном headless Chrome с изолированными данными и существующими API-адаптерами: сохранение сложности и стиля, сохранность отношения, ошибка PUT без потери полей, повторное сохранение и reload; ссылка приглашения, закрытый доступ 0/1, подтверждение серверного флага и переход к 1/1; полный payload создания с NPC/характером/завязкой. Проверены 320/390/1280 px и текст 200%, тёмная тема; снимок формы просмотрен. Основной аккаунт и реальные игровые данные для QA не изменялись; live-сохранение через аккаунт пользователя этой проверкой не заявляется. QA-скрипты находятся вне Git.

## Сверка формы с production 11.11.2026

Сверено с опубликованным frontend-бандлом `index-DdZjS3gV.js`, прежним `WorldAdvanced` и текущими потребителями полей в frontend/backend. Удаление полей по результатам аудита пока не согласовано.

- Основные поля сохранены: имя и роль игрока; название, описание и место мира; начальная ситуация и подсказка; сложность и драма; собеседники с именем, ролью, историей, голосом и чертой; правила; идеи и примеры постов.
- `avatar` в API — исторический ключ портрета/handle. На production он подписан «Ключ портрета», в DEV — «Имя канала». Новая подпись неточна: отдельное имя канала сервер не хранит. Предложение: убрать техническое поле из основной формы и заполнять автоматически; прежнее значение при редактировании сохранять.
- `voice` — манера персонажа игрока (`world.player.voice`), а не общий стиль всех ответов NPC. Каждый NPC имеет собственное поле `voice`. На production подпись «Стиль подсказок для постов», в DEV — «Общий стиль ответов»; обе требуют уточнения. Предложение: «Как пишет твой персонаж».
- `roles` и `voices` на production задавали варианты быстрых настроек. Новый экран их не предлагает, использует прямые поля роли и голоса. Предложение: скрыть оба списка из формы, сохранив существующие данные в payload.
- `summary` подписан как описание карточки, но также используется как запасная цель своего мира. Это неточность текущего отображения; описание карточки не следует выдавать за цель. Отдельного поля цели в этой форме сейчас нет.
- `firstPrompt` используется для подсказки пустой ленты, `postIdeas` — для подсказок под редактором. `demoPosts`: новый frontend берёт первый непустой пример в стартовый черновик; все примеры также передаются модели как примеры, а не события истории. Эти поля работают, но требуют пояснения пользователю.
- Черта с кодом 0 на сервере — `Boldness` («Дерзкость»), в обеих формах названа «Смелость». Предложение: исправить подпись; это черта NPC, не навык игрока.
- Старые редакторы `wants` (включая подпись награды «опыт ×1,3»), `achievements`, стиля DiceBear и ключей портретов NPC не восстановлены. Неизменённые серверные значения при редактировании сохраняются. Обращение к игроку относится к настройкам аккаунта, в редактор мира не перенесено.

Кнопка «Назад»: без изменений возвращает сразу; после изменения поля или портрета показывает видимый модальный Dialog с продолжением редактирования и выходом без сохранения. Прежнее подтверждение было внизу длинной формы и могло остаться вне экрана. Проверены возврат, обе кнопки диалога, сохранность полей при отмене выхода и смена портрета.
