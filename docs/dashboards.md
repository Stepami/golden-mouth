# Представления OpenObserve

Обновлено 12.10.2026. Источники: log streams `product` и `backend`, стандартные OTel metrics и traces. В issue #35 поднимается сбор и хранение; автоматическое provision дашбордов и алертов не входит в MVP.

## Конкурсные показатели

| Показатель | Как считать | Источник |
|---|---|---|
| DAU | `count(distinct player_id)` по календарному дню, `activity_kind = real` | `product` |
| Обращения / DAU | число GenAI operations за день / DAU | `gen_ai.client.operation.duration` и `product` |
| Токены | сумма input/output token usage по модели и операции | `gen_ai.client.token.usage` |
| LLM-cost / DAU | `(input_tokens × input_price + output_tokens × output_price) / DAU`; цены хранятся в версии запроса/дашборда, а не в телеметрии | GenAI metrics + прайс модели |
| Ошибки | 5xx и Error/Critical по часу, route и exception type | HTTP metrics + `backend` |
| Нагрузка | RPS, p50/p95/p99 latency, active requests, GC, allocations, exceptions, thread-pool queue | ASP.NET Core + runtime metrics |

Тестовые и отладочные обращения не должны попадать в конкурсный расчёт. Production-события имеют `activity_kind = real`; тесты проекта не экспортируют OTLP.

## Поля продуктового stream

`ProductTelemetry` пишет плоские log attributes: `event_name`, `player_id`, `event_time_unix_ms`, `received_time_unix_ms`, `session_id`, `platform`, `screen`, `previous_screen`, `world`, `age_group`, `registration_source`, `launch_surface`, `experiment_plus_offer` и разрешённые `prop_*`. Тексты постов, сообщений, комментариев, имена, Telegram ID и `initData` не экспортируются.

Для DAU и когорт используется `player_id`, для сессий — `session_id`. Эти поля допустимы в log stream, но не должны становиться labels OTel-метрик.

## Продуктовый дашборд v2 (#127)

Три вкладки: **Обзор** (текущие аккаунты, DAU/WAU/MAU, календарная активность, stickiness, публикации и подписчики), **Воронка и удержание** (прохождение в горизонтальных полосах с числами; отдельно D1/D3/D7 с eligible), **Активность** (процентная интенсивность по возрастам, посты/время, способ запуска и устройство, ошибки генерации).

Общие single-select фильтры: период анализа 7/30/90 дней, мир, возраст, источник регистрации, способ запуска. Выбор `all` означает все сегменты; `unknown` позволяет видеть неизмеренные старые данные. Запросы воспроизводятся генератором `observability/dashboards/build.py` и общим модулем `product_v2.py`. Источник для каждого запроса — 90 дней, отображаемый диапазон задаёт явный фильтр периода; нативный date picker не должен незаметно обрезать источник для lifetime-этапов и снимка базы.

Дни — по Москве; для подписей графиков открывать с `timezone=Europe%2FMoscow`. Автообновление — `refresh=1m`, поскольку OpenObserve хранит интервал в URL. Текущие аккаунты и их активность используют полный снимок базы не старше 3 минут. Исторический DAU в столбцах включает впоследствии удалённые ID, поэтому не равен автоматически текущему DAU. Проценты retention имеют собственные зрелые базы и не являются этапами последовательной воронки.

Новый прирост подписчиков измеряется только с момента доставки серверного delta, а способ запуска — с момента доставки launchSurface. Неполное покрытие показано в таблицах; NULL не означает ноль. Графики не подменяют отсутствие измерений демо-значениями. Правила полностью описаны в [analytics.md](analytics.md#продуктовый-дашборд-v2--127).

Дополнительный общий переключатель «База воронки и удержания» позволяет исследовать старые профили по первому наблюдению без подмены этого события регистрацией. По умолчанию — подтверждённая регистрация; legacy-режим явно обозначен.
