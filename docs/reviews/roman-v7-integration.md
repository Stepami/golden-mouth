# Frontend v7 — перенос дизайн-системы и границы API (#205)

## Реализация

Frontend использует мобильную дизайн-систему переданного v7: TT Norms Compact/Condensed, theme.css, UI, иконки, социальные действия, профиль и оболочку. Прикладная интеграция — `frontend/src/v7/BackendApp.tsx`; старый API-клиент и сгенерированные DTO не меняются. Дополнительных runtime-зависимостей нет. Возвращающийся игрок начинает с каталога; история выбирается по конкретному worldId.

Реальные серверные операции: каталог/сохранённые миры, обязательная регистрация (14+, обращение), создание истории с ролью, лента с пагинацией, двухэтапная публикация, восстановление статуса, ответы на NPC. Навыки, подписчики и энергия берутся с сервера. Полосы навыков используют серверный progress до следующего уровня, а не level/10; доступное значение отношений NPC сохраняется при преобразовании данных. Поиск/жанры — локальный фильтр загруженных пресетов.

Исходный автономный прототип доступен только в DEV через `?v7demo`, библиотека — `#system`. Это отдельный сценарный просмотр, а не fallback при ошибке API. Production-сборка не включает DemoApp. Изображения миров сопоставлены существующим серверным пресетам; названия и сценарии четырёх демо-миров не выдаются за существующий серверный контент.

## Надёжность

Сохранённая публикация проверяется с исходным UUID, текстом, OwnWords и WantId; новая отправка не передаёт снятый WantId. Незавершённая отправка блокирует смену мира. Результат и списание подтверждает сервер. Ответ сохраняет RequestId и цель при повторе. Неудачное обновление ленты после подтверждения не превращает успешную публикацию в ошибку отправки. Черновики разделены по аккаунту/экземпляру истории; локальные активности содержат worldId. Пустое состояние и «Прочитать всё» ограничены текущей историей. Лайк не открывает модальный диалог. Переход в сохранённый мир показывает busy-состояние; обратная навигация во время переключения блокируется.

Проверки: TypeScript + Vite build; 3 теста подготовки/восстановления публикации; 4 теста mapping реальных форматов ленты, автора треда и дат. В живом DEV API подтверждены каталог, сохранённая история, лента и детали постов; на отдельном тестовом аккаунте — регистрация, создание истории, SSE до ready_for_moderation, подтверждение публикации, расход ровно 1 энергии и отсутствие повторного расхода при повторном подтверждении. Ответ NPC в треде дошёл до серверного failed; успешный ответ этим проходом не подтверждён. Основной DEV frontend обновлён до v7; backend-образ прежний. Полный визуальный проход последней сборки не завершён. Полный parity и готовность к production не заявляются.


## Профиль вне мира

В глобальном профиле есть «Выйти из аккаунта». По текущему требованию это номинальное действие: оно показывает сообщение о недоступности, не вызывает logout API, не очищает авторизацию, миры или черновики. Компонент общий для live UI и отдельного DEV-прототипа.

Редактирование интересов открывает сразу выбранные качества общения и сохраняет прежний выбор. Это не реализация нового жанрового onboarding из предложенных макетов.

Дополнительные проверки: изоляция пустого состояния/прочтения уведомлений между историями; серверный прогресс навыков и отношение NPC; исходные 12 проверок прототипа (демо-правила, контраст токенов, наличие assets). Они не заменяют проверку реального backend и браузерных сценариев.
