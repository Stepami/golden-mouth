Актуально на 04.11.2026. Frontend — draft [#229](https://github.com/Stepami/golden-mouth/pull/229), задача [#205](https://github.com/Stepami/golden-mouth/issues/205). Этот реестр объединяет оставшиеся интеграционные работы; новых issues не требуется. Следующий шаг по backend — Степан. Production не обновлялся и пока не готов к выпуску этой экономики.

## Что можно смотреть

На личном DEV: вход → возраст/согласие → интересы → каталог; реальные миры и отдельная карточка «Спасти Хогвартс»; цель → навыки → подготовленный первый пост; состояния ожидания и результата; профиль, подписчики собственного канала, карта дней, ручное распределение XP, выбор имеющегося бустера. Верхняя панель объединяет ресурсы, серию, подарок и бустеры без внутреннего разделителя. Подарок забирается рядом с серией с анимацией. Профиль: цель → выбираемая карта дней → компактный XP; детали навыков раскрываются при наличии опыта. В песочнице скрыты квест и бустеры, черновик сохраняется. На экране интересов убрана полоска прогресса. «Мои миры» в профиле показывают первые 5, кнопка добавляет следующие 5 без смены мира. Каталог показывает три собственных мира на страницу горизонтального превью, профиль — порции по пять. Длинное описание мира медленно прокручивается, останавливается вручную и учитывает reduced motion. Фавикон использует новую монограмму.

Дизайн использует шрифты и токены Романа: белый фон, чёрный текст, серые поверхности, лаймовое основное действие, фиолетовую энергию. Анимация наград поддерживает reduced motion. DEV-маршрут `/#result-review` показывает явно подписанные дизайн-примеры трёх исходов без публикаций и начисления наград.

**Разделение данных:** посты, ответы, собственные подписчики и технический статус публикации — настоящий API. Сюжетный прогресс, ручной XP, инвентарь и ежедневный подарок — локальная проба, не серверный кошелёк. Сюжетный день содержит 3 квеста; локальный XP освобождается для распределения после закрытия дня. Локальный зачёт подтверждает завершение действия, но не проверяет смысл текста. Полный авторский автомат на сервер ещё не перенесён.

У NPC аудитория показывается только при наличии численного поля API; отсутствие данных обозначено «—», не нулём. Реакции отображаются из фактического ответа API; структурированных межканальных упоминаний пока нет.

## Уже подготовленный backend-кандидат

Draft233, SHA `3ce062a647ad8a6fa1dce31a9fa6b5c1b399a0f1`, открыт отдельно. **Не merged и не deployed.** Степан может использовать его после проверки, это не действующий контракт DEV. В нём предложены GET /me/energy и POST /me/energy/exchange, lazy initialization старых аккаунтов и nullable NPC audience.

Перед внедрением решить судьбу старых остатков выше10, бонусного overflow/Plus и rollback старого runtime. Старое API использует ежедневное восстановление09:00; frontend не подменяет его таймером. Полезны serverNowUtc и типизированные причины отказа обмена. При отсутствии кошелька реальный обмен недоступен — это блокер серверной интеграции, а не успешная UI-покупка.

## Документация и очистка

- Источники правил: `docs/game-flow.md`, `docs/config/balance.json`; новый блок story_economy_proposal отделён от старого runtime.
- `v7-story-pilot.md` сохраняется как описание frontend-пробы; актуальный список backend-зависимостей находится здесь.
- Удалены неиспользуемые StoryDay и XPProfile: старый длинный экран дня и дублирующая проба36XP вводили в заблуждение. Данные пользователя не удалялись.
- Авторский контент-пакет, макеты Романа и draw.io с комментариями сохраняются как исходные материалы. Архивные изображения не являются текущим API/дизайном runtime.
- #219 — база цепочки #229, не удалять до завершения цепочки. #229 остаётся draft. #233 — отдельный backend-кандидат для Степана. Старые PR не закрывать и не мержить автоматически.
- Отдельные незакоммиченные 3D-аватары другого исполнителя не включаются в этот frontend-коммит; их интеграция требует собственного коммита и проверки. DEV содержит эту параллельную работу, поэтому весь DEV нельзя отождествлять с одним SHA frontend.

## Проверки и выпуск

Текущая frontend-сборка проходит; 15 целевых тестов проверяют порядок квестов/дней, release XP один раз, повторную доставку, ручное распределение, подарки и nullable аудиторию. На DEV вручную проверено 5→10 миров профиля. Новых тестовых публикаций при нулевой энергии не отправляли.

Перед production: завершить P0, проверить полный серверный цикл и отказ/повтор/перезагрузку, согласовать продуктовые вопросы, зафиксировать все frontend-исходники и получить итоговый просмотр пользователя. Разрешение личного DEV не разрешает production, backend-деплой или общую миграцию.
